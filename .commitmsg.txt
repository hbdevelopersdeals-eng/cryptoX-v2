Sections 14+15+16+17: analytics, AI architecture, responsive and a11y audits

Analytics (14)
- analytics.js: an event ALLOWLIST with per-event required and optional
  properties, so a typo cannot silently become a second event. Validation refuses
  undeclared properties and any forbidden one, which is what stops an email
  address being attached to an event six months from now.
- The pipeline the brief asks for is processEvent, in that order: validation
  BEFORE anonymization (a rejected event is never partially scrubbed) and
  anonymization BEFORE aggregation. Consent gates the door; reliability events
  pass without marketing consent because a product error is not marketing.
- Pseudonymisation REQUIRES a salt and says why: an unsalted hash of an email is
  reversible by dictionary attack.
- Funnels count only people who did the steps IN ORDER. Counting independent
  totals reported 80 percent where the ordered rate was 50. Retention uses the
  cohort size as denominator, not the previous period. MRR is broken into
  movements, because a flat total hides 40 logos leaving and 41 arriving.

AI architecture (15)
- ai.js: provider registry with an explicit fallback chain ending at the
  deterministic router, so a provider outage means no AI rather than no product.
- Prompt versioning by CONTENT hash, so an edit is detectable without a version
  bump. An undeclared template variable is refused.
- Injection defence is structural first (untrusted content is fenced, and a
  closing delimiter inside the payload is stripped) with pattern detection as a
  signal. Certain patterns are individually DECISIVE rather than weighted, so one
  explicit attempt to send a credential cannot average down to "flag".
- Credentials are refused outright rather than redacted. PII is redacted on the
  outbound payload, so a field added later is covered by default.
- Output validation catches the three failure modes that otherwise look like
  success: a refusal returned as normal text, a truncation that still parses, and
  a missing required field. The audit log stores no prompt or response text.

Responsive (16) and accessibility (17)
- scripts/check-frontend.mjs: mechanical checks that find real things, plus real
  fixes - h-screen and min-h-screen to dvh (100vh sits behind the iOS URL bar),
  aria-hidden on four modal backdrops, and a focus ring restored on the country
  search input.
- The guard's own false positives were the bulk of the work: it scanned single
  lines while JSX attributes span several (150 fake errors), flagged max-w- as a
  fixed width, missed focus-within, mistook min-h-screen for h-screen, and would
  have added aria-hidden to a DIALOG PANEL, which would have hidden dialogs from
  screen readers entirely.
- 71 genuine defects remain: controls whose label is a neighbouring span or p
  rather than a real label. These are RATCHETED, not waived - printed on every
  run with their number, and the count may not grow.
